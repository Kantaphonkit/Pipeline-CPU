Hazards

Three mechanisms, one rule each

The whole correctness story reduces to forwarding, one stall, and one flush.

Forward

EX/MEM and MEM/WB results route straight back to the ALU inputs — no stall for a data hazard.

EX/MEM wins over MEM/WB · x0 never forwarded · store data forwarded too

Stall

A load feeding the very next instruction is the one case forwarding cannot save.

load-use interlock · freeze PC + IF/ID · one bubble into ID/EX

Flush

A taken branch or trap squashes the younger instructions already in the pipe.

jal = 1 bubble · branch / jalr / trap / mret = 2 bubbles · killed insns never retire

bypass interlock flush free

A redirect always overrides a stall — the instruction that raised the stall is being killed anyway.

Everything above CPI 1.0 is control-flow bubbles and load-use stalls. There is no other source of delay in this design.

Why a trace diff

A final-state check tells you the answer is wrong. A commit-trace diff tells you which instruction went wrong — the difference between an afternoon of debugging and a week.

Tests are trusted, not just passing

Every expected value is generated by the reference model, so a test cannot agree with the RTL merely because the same person wrote both. And we injected deliberate bugs to confirm each testbench fails when it should.

Correctness rests on EX-stage resolution + flush — the predictor only changes when instructions are fetched, never what they compute.

The honest part

A 2-bit table helps loop-dominated code (fib 93.4%), is neutral on exit-dominated code, and hurts on alternating branches (49.9%, +10% cycles). We report the adversarial case — it is the predictor's real limit.

The BHT is a cheap heuristic, not a guarantee — and saying so is more useful than hiding the case where it loses.

The trap asymmetry

ecall leaves mepc at the ecall itself, so the handler adds 4 before mret. An interrupt leaves mepc at an instruction that never ran, so the handler must not — mret re-runs it. Get this wrong and the handler loops forever.

I-cache — designed, not built

Direct-mapped 128 lines × 16 B (2 KB) — but the whole test suite fits in 2 KB, so the hit rate would read ~99 % on every program. A figure that reads 99 % proves nothing, so we cut it and wrote the design up instead.

Both bonuses are switchable off — a feature that cannot be disabled cannot be measured.

Critical path — the load-to-branch chain

DMEM block-RAM clock-to-output (2.454 ns, the largest single term) → byte-lane select + sign extension in WB → the MEM/WB→EX forwarding mux → branch comparator → redirect into the PC clock-enable.

Register-to-register hold met at every constraint point; the only hold flags are out-of-context artefacts on the rst port.

A 16-instruction minimum; we shipped 46, verified byte-for-byte, synthesized at 74 MHz — with both bonuses green. Thank you.
